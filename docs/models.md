- 只对向量模型读取 GGUF 元数据中的 `<arch>.embedding_length`
- 模型文件页的「维度」列显示读取结果，例如 `2560`
- 向量模型的 API 弹窗也会显示「维度」
- 元数据缺失或格式不支持时显示 `—` / `未知`
- 读取结果按文件大小与修改时间缓存，不会每次刷新都重新解析

## 导入模型

1. 点击「模型文件」页右上角的「+ 导入」
2. 选择 GGUF 文件，应用在后台复制到程序目录，显示复制进度
3. 导入完成后自动识别类型：
   - 识别为 Embedding 或 Rerank 时，自动分配给对应的模型
   - 识别为 Other 时只加入列表，不自动分配

导入前的预检（毫秒级，在复制开始前完成）：

- 源文件必须是合法的 GGUF（魔数 `GGUF`，版本 1~3），否则报「不是有效的 GGUF 文件」
- 源文件必须存在且非空；源与目标不能是同一路径
- 目标磁盘剩余空间必须足够，不足时给出还差多少

导入使用 `<文件名>.part` 临时文件，完成后再改名；失败或取消都会清理临时文件，
复制完成后再校验一次文件头，防止复制过程中源被改动。

### 同名冲突

目标目录已有同名文件时弹出确认，可选择：

- **覆盖**：目标被运行中的模型占用时禁用（Windows 下不能改动 llama-server 打开的文件）
- **另存为**：输入新文件名（默认 `名称 (1).gguf`），不能与已有文件重名
- **取消**

### 取消复制

复制进行中时，进度行右侧显示「取消」；取消后临时文件被清理，状态栏提示「已取消导入」。

### 自动分配开关

设置页「行为偏好」中的「导入模型后自动分配给对应服务」默认开启。目标服务已有不同的模型时，
会弹出「切换 / 仅导入，不切换」确认，不会静默覆盖当前选择；关闭开关后只导入不分配。

## 导出模型

模型文件页每个模型行的操作列提供「导出」：

1. 选择保存位置（默认文件名为模型名，过滤 `*.gguf`）
2. 应用在后台复制，进度与取消与导入共用
3. 目标文件已存在时同样弹出覆盖 / 另存为 / 取消确认
4. 运行中的模型也允许导出（只读源文件）

导出使用 `<文件名>.part` 临时文件，完成后再改名，目标目录不会出现半截文件。

## 临时文件清理

程序启动时会自动删除模型目录下残留的 `*.gguf.part`（上次复制被中断的产物），
清理结果写入运行日志。只删除应用自有的 `.gguf.part` 前缀，不碰其他文件。

## 运行期产物

模型目录下只有这些由程序维护的文件：

| 文件 | 说明 |
|---|---|
| `config.json` | 应用配置（原子写入） |
| `embedding.pid` / `rerank.pid` | 正在运行的模型进程：第一行 PID，第二行实际端口 |
| `*.gguf.part` | 复制中的临时文件，完成或失败后即删除 |

运行日志只保存在内存里（500 条环形缓冲），可以从「运行日志」页导出到任意位置；
程序不会在模型目录下创建日志文件或 `logs/` 目录。

## 删除模型

模型文件页**不提供删除**：程序只负责扫描与分配，磁盘文件请用资源管理器处理（页面提供「打开目录」）。

- 不再需要的模型直接把 `.gguf` 移出模型目录即可，列表会在 2 秒内自动刷新
- 正在运行的模型显示「占用」，请先停止服务再移动文件

## 选择模型

- 模型下拉只显示与当前模型同类型的 GGUF
- 选择后立即写入 `config.json`
- 启动时仍会检查文件是否存在
- 运行中切换模型不会立即生效，重启后使用新模型
